# 避障识别 — 设计文档

日期：2026-09-28
方案：单目深度估计 + 目标检测
状态：**可行 demo 已跑通；判定逻辑待设计**（见第 7 节）

---

## 1. 背景与目标

用摄像头做图像识别，服务于「避障」，但**只做识别，不做控制**。

- 阶段一：在电脑上运行，摄像头**固定不动**
- 阶段二（未开始）：装到小车上，边移动边避障

## 2. 决策演变：为什么放弃帧差法

项目最初选的是「区域划分 + 帧间差分」（`absdiff` 相邻两帧）。它在实测中暴露了两个问题，最终被放弃。

### 2.1 根本缺陷：检测不到静止障碍

帧差法比较的是**相邻两帧**，检测的是「画面此刻是否在变化」，而不是「画面里有没有东西」。后果：

| 场景 | 帧差法的表现 |
|---|---|
| 障碍物出现后**静止** | ❌ 判定消失——画面不再变化 |
| 一堵始终在那里的墙 | ❌ 从不报警 |
| 慢慢移动进来的物体 | ✅ 能报警，但**一停住就变回「无障碍」** |

更糟的是：防抖要求连续 3 帧命中，而「物体出现」只造成 1 帧变化，**可能连报警都触发不了**。

这个缺陷无法靠调参解决——它是方法本身的性质（帧差法没有记忆）。

### 2.2 阈值困境

实测（本机摄像头，1280×720）：画面静止时噪声占比在 **0.002 ~ 0.026** 之间波动，随光照间歇性升高。

判定阈值必须高于噪声，但噪声本身在变，于是同一个阈值在不同时间表现完全不同：
- 一批素材里 0% 误报
- 另一批素材里频繁误报

这是「无法标定」的问题，不是「标定得不够好」的问题。

### 2.3 结论

帧差法只能回答「有没有东西在动」，而避障需要回答「有没有东西、有多近」。**两者问题不匹配。**

相关代码（`obstacle_detect.py`、`tests/`）与实施计划已删除，git 历史中仍可查。

## 3. 选定方案：深度估计 + 目标检测

**两层分工，各做自己擅长的事：**

```
摄像头帧 ──┬─→ 深度估计 ──→ 每个像素的远近 ──→ 「有没有、有多远」（不挑类别，静止也管用）
           └─→ 目标检测 ──→ 框 + 类别      ──→ 「那是什么」
```

| | 深度层 | 检测层 |
|---|---|---|
| 回答 | 有没有东西、大概多近 | 那是什么 |
| 静止障碍 | ✅ 管用（推理单帧，不依赖帧间变化） | ✅ 管用 |
| 类别限制 | 无（墙、树枝、塑料袋都算） | ❌ 只认训练过的类别（COCO 80 类） |
| 必要性 | **是主判断** | 辅助信息 |

关键点：**检测层是配角**。避障最怕「没见过的障碍物」，而检测层恰恰只能认已知类别；深度层才是不挑类别的那一半。

## 4. 现有实现

文件：`obstacle_detect.py`（避障识别主程序）

```
load_models()            把两个模型加载到 GPU（fp16 半精度）
estimate_depth(proc, model, bgr)
                         整幅画面的远近图 → uint8 灰度（越亮 = 越近）
                         —— 归一化在 GPU 上做完，只把 1/4 大小的数据拷回 CPU
detect(proc, model, bgr, threshold)
                         目标检测 → 框 + 类别 + 置信度，坐标已换算回原图尺度
zone_near_ratios(depth_vis, near_threshold, roi_top)
                         判定的核心（纯函数，可脱离硬件测试）：
                         只看画面下方 roi_top 以下，分 ZONES 区，
                         各算「深度值 > near_threshold 的像素占比」
main()                   主循环：
                         深度每帧都算 → 判定（占比 → 防抖 → 状态）
                         检测每 DETECT_EVERY_N 帧才算一次，但结果被缓存、
                         每帧照画 —— 所以框不会闪，只是位置最多滞后 3 帧
```

可见参数（文件顶部）：

| 常量 | 默认 | 含义 |
|---|---|---|
| `ZONES` | 3 | 分区数（左 / 中 / 右） |
| `ROI_TOP` | 0.5 | 只统计画面下半部分（避障关心的是前方低处） |
| `NEAR_THRESHOLD` | 180 | 深度值 > 此值算「近」（**现场按 `[` `]` 标定**） |
| `MIN_NEAR_RATIO` | 0.10 | 某区近像素占比超过此值 → 该区命中 |
| `CONFIRM_FRAMES` | 3 | 连续命中多少帧才确认（防抖） |
| `DETECT_THRESHOLD` | 0.5 | 检测置信度门槛（检测不参与判定） |
| `DETECT_EVERY_N` | 3 | 每几帧跑一次检测 |
| `CAM_W` / `CAM_H` | 1280 / 720 | 摄像头分辨率 |

按键：`q` 退出 · `[` `]` 调近处阈值 · `n` 开关检测框 · `m` 开关镜像

**性能**（同一批录制帧 + `torch.cuda.synchronize()` 强制同步后测量）

| 项目 | 耗时 | 说明 |
|---|---|---|
| 深度（fp32，初版） | 52.0 ms | |
| **深度（fp16）** | **23.0 ms** | 提速 56%，是当前主要开销 |
| 检测（fp16） | ~9 ms | 隔 3 帧摊薄后约 3 ms |
| **综合** | **34.6 ms → 28.9 FPS** | 优化前为 63.4 ms → 15.8 FPS |

**fp16 的精度代价**：归一化后逐像素平均绝对差 0.00019、最大差 0.0031（<0.3%），视觉上不可辨。

> ⚠️ 测量陷阱（曾经踩过）：CUDA 是**异步**执行的，不在计时点调用 `torch.cuda.synchronize()` 会测出偏小的耗时，从而得出「优化后反而更慢」的假结论。此外，对比不同参数时必须用**同一批录制帧**，否则摄像头读帧时间的波动会污染结果。

## 6. 已知限制

1. **判定阈值是相对值，必须现场标定**。相对深度没有物理单位，所以 `NEAR_THRESHOLD` 只能对着场景调。换房间、换光照可能需要重调——比帧差法轻得多（不再受传感器噪声干扰），但不是零成本。
2. **画面里本来就近的固定物体**（桌沿、镜头前的支架）会被一直算作「近」，可能造成持续误报。
3. **输出的是相对深度，不是米数**。只能说「这块比别处近得多」，不能判断「1 米内」。要真实米数需换 Metric 版模型。
4. **检测层只认 COCO 80 类**，且远处/半身目标的置信度天然偏低——这不是误检，是正常表现（实测确认）。
5. **运动模糊**：深度估计是单帧推理，理论上不依赖帧间关系，因此**相机自身移动不会像帧差法那样直接失效**；但移动带来的模糊会降低深度质量，**尚未实测验证**。
6. **帧率 29 FPS 是上限**，瓶颈在深度推理（占 66%）。要进一步提速需降低模型输入分辨率，那会真实损失精度。
7. **未验证的适用边界**：强光照、纯白墙面、镜面/透明物体等对深度模型的已知难点，均未测试。

## 7. 判定逻辑的设计（已实现）

### 7.1 核心思路：不问「多近」，只问「比别处近多少」

因为用的是相对深度（没有物理单位），绝对阈值没有意义。所以判据是**帧内相对关系**：

```
深度图（uint8，越亮越近）
   ↓ ① 近处掩码：深度值 > NEAR_THRESHOLD 的像素 = 「近处的东西」
   ↓ ② 分区统计：左/中/右三区，各算「近像素占比」
   ↓ ③ 防抖确认：连续 CONFIRM_FRAMES 帧命中 → 确认该区有障碍
```

结构上和被放弃的帧差法几乎一样（分区 → 占比 → 防抖），**唯一的变化是①的输入**：帧差法喂的是「哪里变了」，这里喂的是「哪里很近」。

### 7.2 关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 阈值策略 | **固定阈值 + 现场按键调** | 备选方案是帧内自适应（百分位），但百分位意味着「永远有固定比例的像素被判为近」，空旷场景会稳定误报——这是定义上的缺陷，调不掉 |
| 统计范围 | **只看画面下方 50%** | 摄像头固定朝前时，画面底部才是「前方低处的空间」；上半部分（天花板、远处的墙）掺进来只会稀释信号 |
| 检测层角色 | **不参与判定**，只做显示 | 避障要发现「没见过的障碍物」，而检测层只认 COCO 80 类；深度层才是不挑类别的那一半 |
| 分区数 | 3（左/中/右） | 够用；分区多了每区样本变少，反而更容易被噪声影响 |

### 7.3 仍未决定的问题

- **要不要换 Metric 版模型**？换来真实米数（可判断「1 米内」），代价是模型更大、精度受训练域限制（室内/室外分版）。
- **输出形式**：目前是屏幕色条 + 终端打印，将来接控制层需要固定格式。
- **分区数**是否需要增加（依赖实际使用体验）。

## 9. 附：术语对照

| 术语 | 含义 |
|---|---|
| 相对深度 | 只说 A 比 B 近，没有物理单位 |
| 度量深度（Metric） | 输出近似真实距离（米） |
| fp16 / 半精度 | 用 16 位浮点代替 32 位，速度翻倍、精度略降 |
| 帧间差分 | 比较相邻两帧找变化——本项目已放弃的方法 |
