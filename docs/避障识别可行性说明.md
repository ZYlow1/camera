# 基于单目视觉的避障识别方案 — 可行性说明

日期：2026-09-28
阶段：概念验证（Proof of Concept）已完成

---

## 一、项目目标

为移动机器人（小车）提供**前方障碍物识别**能力，作为避障系统的感知环节。

**本阶段范围**：只做「识别」，不做运动控制。即回答「前方有没有障碍物、在左/中/右哪一侧」，把结果交给后续的控制模块。

**本阶段目标**：验证方案的可行性，为后续硬件投入提供依据。

---

## 二、已完成的工作与实测结果

### 2.1 已实现的系统

一个可实时运行的程序（`obstacle_detect.py`），功能：

- 摄像头实时画面 + 深度估计（逐像素远近）
- 分左 / 中 / 右三区判断「是否有障碍物」
- 判定结果：屏幕分区色条（绿=无障碍 / 红=有障碍）+ 终端状态输出
- 目标检测（识别物体类别）作为辅助信息

### 2.2 实测性能

测试环境：笔记本（NVIDIA GeForce RTX 4070 Laptop，Python 3.12.8，PyTorch 2.6.0+cu124），摄像头 1280×720 @ 30fps。

| 项目 | 实测耗时 | 说明 |
|---|---|---|
| 深度估计（半精度 fp16） | 23.0 ms | 主要开销 |
| 目标检测（每 3 帧运行一次） | ~9 ms | 摊薄后约 3 ms |
| **综合** | **34.6 ms / 帧 → 28.9 FPS** | 已满足实时性要求 |

优化过程（有实测记录）：初版 63.4 ms / 15.8 FPS → 启用 fp16 半精度后 **28.9 FPS**，提速 83%。
半精度的精度代价经实测：归一化后逐像素平均绝对差 **0.00019**（< 0.3%），不影响判断。

模型体积：深度模型约 95 MB，检测模型约 77 MB，均可离线运行、无需联网。

### 2.3 可演示的现象

| 操作 | 系统表现 |
|---|---|
| 物体靠近摄像头 | 对应分区报警 |
| **物体停住不动** | **持续报警**（见 3.2，这是本方案的关键优势） |
| 物体移开 | 恢复正常 |

## 三、技术路线论证

### 3.1 曾尝试的方案及其失败原因

项目最初采用**帧间差分法**（对比相邻两帧，找出画面中变化的区域）。实测后放弃，原因有两个，都是方法本身的性质，**无法通过调参解决**：

**问题一：无法检测静止障碍物（致命缺陷）**

帧差法检测的是「画面此刻是否在变化」，而不是「画面里有没有东西」。因此：

| 场景 | 帧差法的表现 |
|---|---|
| 障碍物出现后**静止** | 判定消失——画面不再变化 |
| 一堵始终存在的墙 | 从不报警 |
| 物体缓慢移入后停住 | 能报警，但**一停住立即变回「无障碍」** |

对避障而言这是致命的：**障碍物静止不动恰恰是最需要被持续识别的情况**。此外，由于防抖需要连续多帧命中，而「物体出现」只造成 1 帧变化，甚至可能连报警都触发不了。

**问题二：判定阈值无法标定**

实测（本机摄像头，1280×720）：画面静止时噪声占比在 **0.002 ~ 0.026** 之间波动，随光照间歇性升高。判定阈值必须高于噪声，但噪声本身在变，导致**同一组参数在不同时间表现完全不同**（同一批参数一次测得 0% 误报、另一次频繁报警）。

这是「无法标定」的问题，不是「标定得不够好」的问题。

### 3.2 现方案：单目深度估计

**原理**：深度模型对图像中每个像素估计其远近，直接回答「哪里近、哪里远」，**不比较帧间变化**。

因此它天然具备帧差法缺失的能力：

| | 帧差法 | 深度估计（现方案） |
|---|---|---|
| 静止障碍物 | ❌ 检测不到 | ✅ **可持续识别** |
| 需要识别物体类别吗 | 不需要 | 不需要（墙、树枝、塑料袋都算障碍） |
| 光照突变 | 会误报 | 影响小 |

**结论**：深度估计是目前唯一能同时满足「发现任意障碍物」和「静止障碍物持续识别」这两个避障核心需求的纯软件方案。

## 四、当前方案的局限（诚实说明）

以下限制均已实测或经几何推导确认，**不是实现不完善，而是当前条件下的固有边界**：

1. **只能得到「相对远近」，不是真实距离**
   当前模型输出的是相对量（无物理单位），可以说「这块比别处近得多」，但**无法判断「1 米以内」**。要获得真实距离需更换度量（Metric）深度模型或加装深度相机。

2. **受摄像头摆位限制**
   经几何计算：摄像头离地 0.3 米、水平朝前时，**画面最下方对应的地面距离约 0.72 米**——即 0.3 米处的地面根本没有进入画面。因此「判断 0.3 米内有无障碍」在当前摆位下**没有可用的像素数据**。
   要覆盖近处，需将摄像头朝下倾斜（约 25°）或降低安装高度（约 15 cm）。

3. **依赖 GPU**
   实测纯 CPU 运行帧率过低（个位数），需 CUDA 显卡。上车时需要相应的算力平台。

4. **尚未验证的场景**
   摄像头自身移动（车载）、强光照、纯白墙面、镜面/透明物体等，均**尚未实测**。

> 说明：第 1、2 条正是后续需要硬件投入的直接原因。

## 五、进一步研究所需条件（经费依据）

要从「概念验证」推进到「可用于小车避障」，需要以下条件：

| 需求 | 用途 | 解决的局限 |
|---|---|---|
| **深度相机** | 直接输出真实距离（米） | 局限 1：摆脱相对深度，实现「1 米内」这类判断 |
| **可调角度的摄像头支架 / 车载安装位** | 前下方俯视安装 | 局限 2：让近处地面进入视野 |
| **车载算力平台** | 脱离笔记本独立运行 | 局限 3：车载实时运行 |
| **移动平台（小车底盘）** | 验证移动场景 | 局限 4：相机自身移动时是否可用 |

> 具体型号与价格需按实验室采购渠道询价后确定。
> 建议优先验证「深度相机 + 车载安装位」两项——它们是解决局限 1、2 的最小充分条件。

---

## 六、结论

1. **软件方案已验证可行**：已实现可实时运行（28.9 FPS）的避障识别原型，能对静止与运动障碍物持续识别，解决了帧差法无法检测静止障碍物的根本问题。
2. **当前瓶颈不在算法，在硬件**：真实距离信息与近处视野这两项，受限于现有摄像头与摆位，是**物理上无法用软件弥补**的。
3. **下一步的最小充分投入**：深度相机 + 可调角度的安装位，即可把「相对远近」升级为「真实距离 + 近处覆盖」，从而具备实际避障能力。
